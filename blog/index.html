从一个静态网页开始理解 Web

陈俊强 · 中国科学技术大学 · 人工智能专业

之前我基本只是在使用网页，这次自己从头搭了一遍，才开始注意浏览器背后实际发生了什么。 表面上看，HTML 负责内容、CSS 负责样式、JavaScript 负责交互； 但把页面放到网络上以后，就会冒出新问题：浏览器到底怎么拿到这些文件？ 服务器又用什么协议把它们返回给我？

1. HTML 是页面的骨架

HTML 的作用不是把页面“变漂亮”，而是描述页面结构。标题、段落、图片、链接， 都是浏览器能够理解的结构化内容。这个主页中的导航栏、项目卡片、图片与超链接， 都由 HTML 组织起来。

2. CSS 让结构变成视觉体验

CSS 把布局、字体、间距、颜色与响应式设计从 HTML 中分离出来。 这样调整视觉风格时，不需要反复修改正文结构。本项目把主要样式统一放在 assets/css/main.css 中，主页与博客页共同复用。

3. JavaScript 只做必要的增强

这个站点没有使用复杂的前端框架。JavaScript 只负责明暗主题、移动端导航、 滚动出现动画等少量增强。即使脚本没有加载，网页的核心内容仍然能够阅读。

4. 发布后，网页才真正进入“网络”

本地双击 index.html 可以看到页面，但这还不是公开网站。 当网页部署到 GitHub Pages 等静态托管平台以后，浏览器会通过 HTTP/HTTPS 请求这些资源。 此时就可以使用浏览器开发者工具，在 Network 面板查看实际使用的协议版本。

5. 从 HTTP/1.1 到 HTTP/2、HTTP/3

HTTP 的不同版本在连接复用、并发传输和延迟方面一直在改进。 把这个网站部署到 GitHub Pages 之后，我在 Chrome 的 Network 面板里看到 主页文档的 Protocol 是 h2，也就是这次访问实际使用了 HTTP/2。 协议版本是客户端和服务器连接时协商出来的，所以这里记录的是这次访问观察到的结果。

6. 一点体会

做完这个页面以后，HTML/CSS 和计算机网络这两块知识算是接上了： 网页里的 HTML、CSS 和图片都是应用数据，HTTP 是传输这些数据的应用层协议。 HTTP/1.1 和 HTTP/2 通常运行在 TCP 之上，而 HTTP/3 使用 QUIC； 再往下还有 IP 和链路层。一个很简单的网页，其实把整条链路都串了一遍。
